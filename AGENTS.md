AGENTS.md — Правила разработки проекта «Умный дом»
1. Общие принципы и среда разработки (Windows 11)
Ты — Senior Fullstack-разработчик. Проект представляет собой многостраничный коммерческий сайт услуг по проектированию и монтажу беспроводных систем умного дома (протоколы: Zigbee, Matter, Thread; платформы: Home Assistant, Sprut.hub, Яндекс Алиса; оборудование: Aqara, Sonoff, Sprut, Tuya Zigbee).

Критически важные правила для ОС Windows 11:

Разработка ведётся локально на Windows 11 (D:\Project\...) в оболочке PowerShell / CMD.
Запрещено использовать Unix-специфичные команды в терминале и npm-скриптах (rm -rf, cp -r, export KEY=val, chmod, grep, cat и т.п.). Использовать PowerShell-команды (Remove-Item -Recurse -Force, Copy-Item), Node.js-скрипты или кроссплатформенные утилиты (cross-env, rimraf).
Для работы с путями внутри Node.js-кода всегда использовать модуль node:path (path.join, path.resolve), никогда не склеивать пути строками через / или \.
Обязательно поддерживать файл .gitattributes с * text=auto eol=lf (особенно для .sh, Dockerfile, конфигов), чтобы код, написанный в Windows, без ошибок собирался в Linux Docker-контейнере на VPS.
2. Технологический стек и ограничения
Framework: Next.js (App Router), React 19, TypeScript ("strict": true).
Styling: Tailwind CSS + Framer Motion для анимаций.
PDF Generation: @react-pdf/renderer (клиентская генерация сметы без нагрузки на сервер и внешних API).
Validation: Zod (обязателен для всех форм, параметров калькулятора и API routes).
Testing: Vitest + React Testing Library (unit/integration), Playwright (E2E).
Запреты:
Не использовать any в TypeScript.
Не подключать внешние CDN в рантайме (шрифты, включая шрифты для PDF-генератора, иконки и скрипты должны бандлиться локально из /public/fonts для стабильной работы в РФ без VPN).
Не устанавливать тяжёлые UI-библиотеки целиком (Material UI, Ant Design и т.п.) — писать лёгкие кастомные компоненты.
3. Дизайн-система и UX
Тема: Строго тёмная (#090D16 / #0F172A — основной фон, #1E293B — карточки с эффектом glassmorphism).
Акценты:
Тёплый свет/комфорт: янтарно-золотой (#F59E0B / #FBBF24) — для сценариев освещения, климата и CTA-кнопок.
Технологичность/датчики: неоново-бирюзовый (#06B6D4 / #22D3EE) — для схем, индикаторов, бейджей брендов и технических блоков.
Динамика: Использовать Framer Motion для плавного появления блоков при скролле, интерактивного отклика в калькуляторе и микро-анимаций. Учитывать prefers-reduced-motion.
4. Архитектура и функциональные требования
Многостраничность:
/ — Главная (УТП, интерактивная схема беспроводного дома, обзор поддерживаемых брендов Aqara/Sonoff/Sprut, этапы работы, мини-калькулятор, кейсы).
/services — Услуги и готовые комплекты (Свет, Климат, Шторы, Безопасность и протечки, Мультирум) с разбивкой по ценовым сегментам оборудования.
/calculator — Полноценный интерактивный калькулятор сметы:
выбор типа объекта (квартира/дом), площади, количества комнат;
выбор центрального контроллера/экосистемы (Home Assistant + Sprut.stick, Sprut.hub, Aqara Hub, Яндекс Станция);
выбор предпочтительного бренда/ценового сегмента периферии (Бюджет: Sonoff / Tuya Zigbee; Оптимум: Aqara / Sonoff; Премиум/Локальный: Sprut + Aqara);
формирование спецификации (количество реле, датчиков, карнизов, стоимость оборудования + стоимость монтажа и пусконаладки);
кнопка «Скачать PDF-смету» и кнопка «Отправить смету инженеру» (в Telegram/MAX-бота).
/portfolio — Реализованные проекты, примеры сборки слаботочных щитов, схем автоматизации и используемых устройств.
/contacts — Контакты, форма обратной связи, прямые ссылки на Telegram/MAX-ботов.
API и интеграции с ботами (/api/*):
Вся логика расчёта стоимости и подбора спецификации оборудования должна быть вынесена в чистые функции (src/lib/calculator/) для переиспользования на клиенте, сервере и в тестах.
API-роуты для отправки заявок и смет в Telegram/MAX должны работать через серверные переменные окружения (process.env).
5. Безопасность (Security First)
Все секреты (токены ботов, Chat ID, ключи API) хранить исключительно в .env.local (не коммитить в Git, поддерживать актуальный .env.example).
Никогда не передавать токены ботов на клиент (никаких NEXT_PUBLIC_ для секретов).
Все входящие POST-запросы в app/api/* валидировать через Zod-схемы; при невалидных данных возвращать 400 Bad Request.
Реализовать защиту от спама (honeypot-поле в формах + базовый in-memory rate limiter на API-роутах).
Санитизировать пользовательский ввод перед форматированием сообщений для Telegram/MAX (защита от Markdown/HTML-инъекций в сообщениях бота).
6. Тестирование (Пирамида тестирования)
Ни одна задача не считается завершённой без тестов:

Unit-тесты (обязательно 100% покрытие бизнес-логики): расчёт сметы по брендам (Aqara, Sonoff, Sprut), подбор количества датчиков/реле по площади, валидация Zod-схем, форматирование сообщений для ботов.
Component-тесты: проверка интерактивности калькулятора (смена бренда оборудования и пересчёт сметы, рендер кнопки генерации PDF), валидация полей форм.
Сборка и завершение процессов: перед завершением этапа проверять успешность npm run test -- --run (флаг --run обязателен в Windows, чтобы Vitest не зависал в watch-режиме), npm run lint и npm run build.
7. Совместимость с деплоем (Vercel + РФ VPS)
В next.config.ts всегда сохранять настройку output: 'standalone'. Примечание: локально на Windows при npm run build с output: 'standalone' Next.js может выдавать предупреждение о симлинках (EPERM без прав администратора) — это нормально для локальной сборки на Win 11, в Linux Docker-образе сборка пройдёт чисто.
Не завязываться на проприетарные сервисы Vercel (Vercel KV, Vercel Edge Config и т.п.) — использовать стандартный Node.js runtime, чтобы проект без правок кода собирался в Docker-контейнер для переноса на российский VPS.
